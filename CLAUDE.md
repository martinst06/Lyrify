# Lyrify — Claude context

## What this is

A macOS floating lyrics window for Spotify. SwiftUI, Swift package, no external dependencies beyond the standard library. Reads the current Spotify track via AppleScript; shows Spotify's own lyrics when configured, else synced LRC lyrics from LRCLIB; displays them in a frosted-glass always-on-top window with auto-scroll and click-to-seek.

## Project layout

| Path | Purpose |
|------|---------|
| `Sources/Lyrify/main.swift` | Entry point — creates the NSWindow + AppDelegate, registers spacebar shortcut |
| `Sources/Lyrify/SpotifyBridge.swift` | All AppleScript calls: track info, play/pause, next/prev, seek |
| `Sources/Lyrify/SpotifyLyricsService.swift` | Spotify's own lyrics (first source) — `sp_dc` cookie + TOTP → web-player token → private `color-lyrics` endpoint; publishes `SpotifyLyricsWarning` for the warning icon |
| `Sources/Lyrify/LyricsService.swift` | Tries `SpotifyLyricsService` first, then LRCLIB — exact match (`/api/get`), then search (`/api/search`) with synced-first, closest-duration tiebreak; falls through to `GeniusService` when LRCLIB has nothing |
| `Sources/Lyrify/GeniusService.swift` | Last-resort **plain-text** fallback — finds the song via Genius search (official API if `geniusToken` set, else public web search) and scrapes lyrics from the page HTML |
| `Sources/Lyrify/LRCParser.swift` | Parses `[mm:ss.xx]` LRC timestamps into `[LRCLine]` |
| `Sources/Lyrify/PlainScroll.swift` | Pure pace math for unsynced lyrics: playback fraction + target line index (unit-tested) |
| `Sources/Lyrify/LyricsViewModel.swift` | Poll loops (track change 0.8s, position sync 0.4s), `seek(to:)`, next-track lyric preload, plain-lyric progress |
| `Sources/Lyrify/ContentView.swift` | SwiftUI view — synced lyrics scroll + `PlainLyricsView` (estimated auto-scroll), playback controls, hover cursor, click-to-seek, yellow Spotify-lyrics warning icon (bottom-left) |
| `Sources/Lyrify/SpotifyConfig.swift` | Reads optional `~/Library/Application Support/Lyrify/config.json` (`clientId`, `geniusToken`, `spDc`); absent ⇒ Web API off / Genius uses public search / Spotify lyrics off |
| `Sources/Lyrify/SpotifyAuth.swift` | Spotify Web API OAuth (PKCE), loopback callback, token store/refresh (`tokens.json`, 0600) |
| `Sources/Lyrify/SpotifyWebAPI.swift` | `GET /me/player/queue` → next track, used only to preload lyrics |
| `Tests/LyrifyTests/LyrifyTests.swift` | Unit tests for the pure logic (PKCE, token/queue/HTTP parsing, Spotify TOTP + lyrics parsing) — `swift test` |
| `app/Info.plist` | App bundle metadata (`com.user.lyrify`, macOS 13+) |
| `app/AppIcon.icns` | App icon (generated by `app/make-icon.py`) |
| `app/make-icon.py` | PIL script to regenerate the icon — dark squircle, dim lyric bars, one green (Spotify green `#1db954`) active line |
| `build-app.sh` | Builds release binary + assembles `Lyrify.app` (default dest: `~/Desktop`) |
| `LaunchAgent/com.user.lyrify.plist` | Optional login-item plist — points at `/usr/local/bin/lyrify` |

## How to build

```bash
swift build -c release                    # compile only
./build-app.sh                            # compile + assemble ~/Desktop/Lyrify.app
./build-app.sh /Applications              # or install to Applications
```

After any source change, re-run `./build-app.sh` to refresh the desktop app. Run `swift test` for the unit tests.

### Next-track lyric preload (optional)

Uses the Spotify Web API to learn the upcoming song and warm `LyricsService`'s cache so track
changes are instant. Disabled unless configured; never affects the AppleScript→LRCLIB path.

1. Spotify Developer dashboard → your app → copy **Client ID**.
2. Add Redirect URI `http://127.0.0.1:8888/callback`.
3. `~/Library/Application Support/Lyrify/config.json` → `{ "clientId": "…" }`.
4. Launch Lyrify; on the first track change a browser opens once to authorize (`user-read-playback-state`). Tokens persist in `tokens.json` (0600) and refresh silently after.

### Spotify's own lyrics (optional, first source)

1. Log in at open.spotify.com → DevTools → Application/Storage → Cookies → copy `sp_dc`.
2. Add it to `config.json` → `{ "spDc": "…" }`. The file should be 0600; the cookie is full account access.
3. Lasts ~1 year. After expiry, sign-out, "Sign out everywhere", or a password change, a yellow ⚠ appears bottom-left (click opens `config.json`); paste a new cookie and the next track change picks it up.

> **Important — new machine setup:** Always run `./build-app.sh` after cloning. Never copy
> `Lyrify.app` from another machine — the app must be compiled natively or lyrics will hang
> on "Loading…" due to URLSession not working correctly in a copied binary.

To regenerate the icon after editing `app/make-icon.py`:
```bash
python3 app/make-icon.py   # overwrites app/AppIcon.icns + app/icon-1024.png
./build-app.sh             # rebuilds the app bundle with the new icon
```

## Architecture notes

- **No Combine, no async/await** — two background poll loops with `Thread.sleep` + `DispatchQueue.main.async`. Simple and stable.
- **Never block a shared GCD pool thread.** All blocking work runs on dedicated serial queues, never `DispatchQueue.global().async`: lyric fetches on `LyricsViewModel.fetchQueue`, the concurrent search inside `fetchSync` on `LyricsService.searchQueue`, AppleScript commands on `SpotifyBridge.commandQueue`. Blocking the shared pool (a `sem.wait`/`waitUntilExit` per no-lyrics song, plus button taps) used to exhaust it and freeze the whole app.
- **LyricsService.fetchSync is blocking** — run it on `LyricsViewModel.fetchQueue`, decoupled from the track-change loop so a slow/lyric-less song can't stall detection. Don't call it from the detection loop or the main thread.
- **Background loops don't touch the main thread synchronously.** The position loop reads `lines`/`activeIndex`/`isPlaying` from `stateLock`-guarded snapshots (kept in sync by `setLines`/`setActiveIndex`), never `DispatchQueue.main.sync`. Reconcile `isPlaying` every tick, before any empty-lyrics early return.
- **Spotify's lyrics always win** in `LyricsService`, synced *or* plain, looked up by Spotify track ID (only valid 22-char base62 IDs). Then LRCLIB, then Genius.
- **Spotify login failures**: token-endpoint 401 (or an anonymous token) ⇒ bad cookie, blocked until the `spDc` value changes; 400 ⇒ stale TOTP secret, re-downloaded once, then blocked 10 min. Either shows the warning icon until a login succeeds. No response (offline) blocks nothing.
- **Lyrics matching strategy** in `LyricsService` (LRCLIB part): `/api/get` exact match first; if it returns plain-only, don't stop — keep searching. `/api/search` scans all results, picks the synced candidate closest to the track's duration. Only falls back to plain text if no synced version exists anywhere.
- **Click-to-seek**: `vm.seek(to:)` sets `activeIndex` optimistically for instant visual feedback, then calls `SpotifyBridge.seek(to:)` (which dispatches to `commandQueue`). The position loop reconciles within ~0.4s.
- **Track identity includes Spotify's track ID**, not only title/artist, so distinct recordings with identical metadata still reload lyrics and reset per-song UI state.
- **`nonEmpty(_:)`** in LyricsService collapses both `null` and `""` from LRCLIB to nil — LRCLIB returns both forms for absent lyrics.

## Key design decisions

- **Spotify's own lyrics are the primary source when `spDc` is set** (`SpotifyLyricsService`). The user wants exactly what the Spotify app shows; LRCLIB misses many non-English tracks Spotify has (Musixmatch-sourced). Unofficial and against Spotify's ToS (personal use only): the private `color-lyrics` endpoint only accepts web-player tokens, minted from the `sp_dc` cookie plus a TOTP whose secret is fetched at runtime from the community repo `xyloflake/spot-secrets-go` (Spotify rotates it). Developer-app OAuth tokens reportedly don't work there (not verified here). Token lives in memory only.
- **LRCLIB is the fallback** (and the first source without `spDc`). Free, legit, no API key. Coverage is patchier for non-English/folk tracks but the matching logic is tuned to find synced versions LRCLIB does have.
- **Genius is a last-resort, plain-text-only fallback** (`GeniusService`), tried only when LRCLIB returns nothing. Genius has no lyrics-in-API, so the words are scraped from the song page HTML — unsynced, rendered through the same plain-text path as an LRCLIB plain result. Fragile by nature (breaks if Genius changes its markup) and ToS-gray; kept for personal-use coverage of tracks LRCLIB misses. Optional `geniusToken` only improves the song-matching step, never returns lyrics itself. Scrape targets `<div data-lyrics-container>` and drops `data-exclude-from-selection` chrome subtrees.
- **Plain (unsynced) lyrics auto-scroll on an estimate, not timestamps** (`PlainScroll` + `PlainLyricsView`). With no per-line timing there's nothing to highlight or seek to, so the whole block drifts down at a rate assuming the lines are spread evenly across the song: `plainProgress` (playback fraction, published by the position loop) → target line index. It's deliberately rough (intros/outros/instrumentals throw it off). A per-song speed slider (bottom-right of the controls) adjusts mid-song pacing (75–125%) while still reaching the final line at song end; synced lyrics ignore it. The setting resets to 100% on track change. A manual scroll suppresses the auto-scroll for ~4s (`PlainLyricsView` tells its own programmatic scroll from a user scroll via a `GeometryReader` offset + a short "programmatic" window), then it re-syncs. No click-to-seek for plain lines.
- **Ad-hoc codesigned bundle**. Locally built so no quarantine. No Apple Developer account needed.
- **`build-app.sh` is the canonical way to install**, not `sudo cp`. It handles the full bundle assembly including icon.
